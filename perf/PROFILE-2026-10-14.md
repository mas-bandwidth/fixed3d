# Fixed3D profiling refresh — 2026-10-14

**Disposition: partial / not done.** This report provides the requested b3Profile phase timings for the available Linux hosts. It does not contain top-15 functions by hardware sample percentage: the hosts deny PMU access (`perf_event_paranoid=4`), and no hardware sampling was run. The authorized in-process function hook produces diagnostic self-time, not sample counts; its large overhead changes how many simulation steps fit in each window. No sample-percent ranking can be truthfully derived from it.

The brief says “five buckets” but enumerates six. This report uses the six enumerated categories. Each phase table row below is measured from the harness. Phase intervals are nested/overlapping, so values are independent phase costs and must not be summed as a partition. The timer includes the complete final step crossing the 3-second boundary. `steps` is reported for trajectory context only; different worker counts and hook modes can advance different numbers of steps, so do not interpret them as speedups.

## Coverage and method

All 13 harness scenes were captured at workers 1 and 4 on Vision (AMD Ryzen Threadripper 2990WX, scalar control) and b3 (AMD Ryzen 7 255 with Radeon 780M, scalar control plus `BOX3D_AVX512`). Each run used exactly 20 warm-up steps followed by a 3,000,000,000 ns in-process capture, with the actual benchmark command pinned to CPUs 0–3 and launched at nice 10. There was one serialized driver per host. The scripts validated exit status, exact profile markers, scene/worker/warmup/window, fresh per-run output, phase headers, and function-hook output where enabled. The b3 driver validated 104 rows; Vision validated 52.

The accepted matrices were run with Linux PMU access unavailable at `perf_event_paranoid=4`; no sudo perf attempt or system/service change occurred during those accepted runs. Earlier diagnostic activity, excluded from these results, temporarily lowered the setting and invoked sudo perf; the setting was restored to 4 and Rowan verified the restoration. No sample data from that diagnostic is included. Thus the requested perf samples and top-15 sample percentages are absent. In-process function instrumentation is supplementary only: it materially slows the run and changes the simulated trajectory. On Vision scalar, plain runs covered 18–7,684,659 steps while instrumented runs covered 1–292; on b3 scalar, the ranges were 24–11,176,305 and 1–383, respectively. Do not compare hook symbol shares to the plain phase data as if they described the same workload.

Vision’s per-run `process.txt` affinity snapshots raced before `taskset` and show 0–63. The runner command is pinned to 0–3; during the run, the operator observed `/proc` showing `Cpus_allowed_list: 0-3`, NI=10, and PSR in 0–3. That live observation was not saved as a separate artifact, so the archived snapshots alone do not prove actual affinity. The b3 runner waited for live affinity 0–3 before saving its process metadata. Both hosts’ `cpu_info.sh` evidence and manifests are preserved in the archives.

The requested Apple Silicon `BOX3D_NEON` leg is missing. The authorized mini-M5 host had Apple Clang but no existing CMake executable in checked paths; installation was prohibited, so no build or run occurred. No Mac/Studio was used. No AVX2-wide run was possible: Vision’s available build path did not support the wide variant, so that cell is marked unavailable. The stale earlier Vision batch (with a worker clamp and earlier source) is excluded.

## Function-level diagnostics and requested symbol rankings

The profile helper was compiled with `-finstrument-functions` in separate diagnostic binaries, with LTO and `-O3 -g`, frame pointers enabled. Their function CSVs and exact binary symbol maps are preserved in the raw archives. Because instrumentation overhead is large and per-scene step counts diverge sharply from uninstrumented runs, these self-time totals are not hardware samples, cannot be converted to percent of samples, and are not presented as the requested top-15 rankings. No function-level “hotspot” claim is made here.
