# `f555ee4` "Optimize Broad-Phase (#159)" — layer list, bottom up

For your correction; nothing is built until this is corrected. Read-only against
`<fixed3d clone>` (fixed3d main `4077698`, `upstream/main` `5d83df8`),
from `fixed3d#65` row 2 and the T1 triage, every leaned-on claim re-verified. Evidence at the end.

## The end result

fixed3d's broad phase becomes a tree-against-tree pair traversal over a dynamic tree whose nodes are
sibling-paired at even indices with a resident empty sentinel at index 1, parents and cold proxy data in
side arrays, and per-worker 64-bit pair keys merged and sorted before contact creation. It must still be
bit-identical for a given input on every platform, in narrow and `LUDICROUS_MODE`, at every worker count
the suite runs — and the sort makes contact order a function of the pair *set* alone, independent of
worker count and of tree shape.

## L1 — the empty AABB in Q48.16 (the no-infinity floor)

STRUCTURE: the sentinel value (`B3_BOUNDS3_EMPTY`, `src/math_internal.h:22`), `b3Perimeter`
(`src/aabb.h:12`), the scalar `#else` arm of upstream's new `b3AABBV` block ported into `src/simd.h`.

GUARANTEES:
1. `b3Perimeter` is never called on an AABB with `upperBound < lowerBound` in any component.
2. Overlap against the sentinel is false for every AABB including itself — comparison only, so
   `±B3_FIXED_MAX` behaves exactly as `±INFINITY`.
3. Union with the sentinel is the identity — min/max only, same.
4. No scale, transform or inflate ever touches a sentinel bound.

WHY FIRST: upstream leans on IEEE saturation at the arithmetic sites and never calls `b3IsEmptyNode`
there. Narrow, `-B3_FIXED_MAX - B3_FIXED_MAX` wraps to +huge (rule 4); in `LUDICROUS_MODE` the widths are
`__int128` and do not wrap, but `b3Perimeter` assigns into a 64-bit `b3Fixed` and truncates — the two
configs wrap differently. Already hit in this file (2026-07-11 audit; the count-based skip still stands
at `src/dynamic_tree.c:1745`). That skip worked because the empty box was transient scratch in one
function; the new design makes it resident, so the skip becomes an invariant.

CHECKED BY: new `TreeEmptyNodeArithmetic` over a 1-proxy tree, a 0-proxy tree and a tree with one free
sibling pair — area ratio, refit, rebuild, query, ray cast and `_Load` all complete with no
`±B3_FIXED_MAX` bound escaping into a result; plus a VALIDATE assert at the head of `b3Perimeter`, seen
firing before it is trusted. HELD: question 1.

## L2 — node, proxy and tree layout, and the serialized identity

STRUCTURE: `b3TreeNode`, new `b3TreeProxy`, `b3DynamicTree`, `b3CompoundData::proxyOffset`
(`include/box3d/types.h`); `B3_DYNAMIC_TREE_VERSION` (`:1709`), `B3_COMPOUND_VERSION` (`:2441`),
`B3_SNAP_VERSION` (`src/world_snapshot.c:36`), `B3_REC_VERSION_MINOR` (`src/recording.h:95`).

GUARANTEES:
1. `sizeof` and `_Alignof` of `b3TreeNode` are asserted config-agnostically, in the
   `sizeof(b3AABB) - 2*sizeof(b3Vec3)` style of `src/hull.c:2790`. There is none on `b3TreeNode` today.
2. `nodeEnd` is even and a sibling pair never straddles a node boundary — alignment, not packing.
3. Every version counter is fixed3d's own number; no upstream constant is copied.
4. A file written by any earlier fixed3d is refused, never reinterpreted.

LAYOUT FACT, computed from field sizes, not yet measured: `b3AABB` is 48 bytes narrow and 96 wide
(`fixed_compat.h:267,309`), so the node is 56 narrow and 104 (padding to 112) wide against upstream's 32.
Upstream's premise — "two nodes fit in a 64 byte cache line" — is false in both configs. Still a win
(ours is 72 today), but the pairing buys index arithmetic and alignment, not packing; the port record
says so and the comment is not copied.

VERSIONS: `B3_DYNAMIC_TREE_VERSION` currently equals upstream's *pre-image* and is XORed into
`B3_COMPOUND_VERSION`, so a fresh constant is minted rather than taking upstream's `0x1D6F4C2A73B80E91` —
sharing it would let a box3d tree file and a 56-byte fixed3d tree file claim one layout.
`B3_SNAP_VERSION` 2 -> 3, our counter, not upstream's 5. Recording minor is question 4.

CHECKED BY: the asserts in all four configs; `test_compound.c`'s `nodeEnd >= 2` / `proxyCount` /
`proxies != NULL` conversion; a new case feeding a pre-port tree, compound and snapshot file and
asserting refusal. HELD: questions 2 and 4.

## L3 — tree index structure: sibling pairs, free lists, the resident sentinel

STRUCTURE: `tree->nodes`, `parents`, `proxies`, `nodeEnd`, `pairFreeList`, `proxyFreeList`,
`proxyCapacity`, `dfsOrdered`; the new `src/dynamic_tree.h`. All integer; its only non-portable line is
`b3MakeEmptyNode`, which becomes `B3_BOUNDS3_EMPTY` (L1).

GUARANTEES — upstream's own `b3DynamicTree_Validate` asserts, promoted to invariants:
1. `nodeEnd` even, `2 <= nodeEnd <= nodeCapacity`, `parents[0] == B3_NULL_INDEX`.
2. Node 1 is always empty; a free pair has both slots empty; a pair reachable from the root has at least
   one non-empty slot. This is what makes L1 guarantee 1 true.
3. `nodeEnd == 2*max(proxyCount,1) + 2*freePairCount`; `proxyCount + freeProxyCount == proxyCapacity`.
4. `proxyCount == 0` implies the root is empty.
5. Traversal stacks stay under `B3_TREE_STACK_SIZE` (512), the cross-seed queue under 128.

CHECKED BY: TLA+ `DynamicTreeIndex.tla`, written before the branch — variables `nodes` (each
`empty|leaf|internal`), `parents`, the two free lists, `nodeEnd`, `dfsOrdered`; actions CreateProxy,
DestroyProxy, MoveProxy, Refit, Rebuild; invariants 1-5. TLC instance 4 proxies / nodeCapacity 12 /
proxyCapacity 4, serial — exhaustive. Then `TreeDestroyScrambled`, `TreeLeafRoot`, and
`b3DynamicTree_Validate` under Debug+VALIDATE in every existing suite. HELD: nothing — upstream's
integer design, ports verbatim once L1 and L2 are settled.

## L4 — the moved-bit protocol

STRUCTURE: the `B3_MOVED_NODE` bit in `flagIndex`; `b3DynamicTree_MarkProxyMoved` (atomic fetch-or up
`parents` with an early break), `_MarkProxyMovedSerial`, `_ClearMoved`, `_GatherMovedProxies`,
`b3HasTreeMoved`, `b3NeedsRebuild`; `b3AtomicLoadU32Raw` / `b3AtomicFetchOrU32`. Replaces
`movedProxies[]`, `moveArray`, `b3BufferMove` (`src/broad_phase.h:31-34,69-79`) and `solver.c`'s
`enlargedSimBitSet` serial union.

GUARANTEES:
1. For every node reachable from the root, the moved bit is set iff some leaf beneath it is marked. The
   early break is only correct under upward closure, and `_ClearMoved` descends only through moved nodes,
   so a violation leaves stale bits for the life of the tree.
2. The final bit state after a step is independent of worker interleaving, early break included.
3. `_ClearMoved` leaves no moved bit set anywhere.
4. All of the above hold across insert, move, remove, refit and rebuild — rebuild rewrites every index,
   so the bits are rebuilt with them.

CHECKED BY: TLA+ `TreeMovedBit.tla`, written before the branch — variables the per-node bit and a
per-worker program counter; actions MarkLeaf, StepUp, Break, Clear, Rebuild; invariants 1-3 plus
termination. TLC instance a fixed 7-node tree (3 leaves), 2 workers marking concurrently. Then
`CountEnlargedNodes` -> `CountMovedNodes`, the rewritten `TestEnlargedProxyDestroyed` (expectation
inverts: `> 0` becomes `== 0` plus `ENSURE( tree->dfsOrdered )`), and `_ValidateNoMoved` under VALIDATE.

REWRITTEN, NOT PORTED: `SleepingWorldTreeJoinTest` (`test/test_world.c:1389`, landed as `f424584`)
asserts `tree->nodes[tree->root].flags & b3_enlargedNode` at `:1419` and `:1427`; both `tree->root` and
`b3_enlargedNode` are deleted here. The claim survives, spelled `b3HasTreeMoved( tree )`, seen red first.
HELD: nothing.

## L5 — SAH partition and rotate in fixed point

STRUCTURE: `b3PartitionSAH` (`src/dynamic_tree.c:1656`, called from `:1856` and `:1960`), the
rotate/balance cost block, `b3DynamicTree_GetAreaRatio`.

GUARANTEES:
1. No float in a rebuild path. `:1691` is `invD = invD > 0.0f ? 1.0f / invD : 0.0f;` and `:1696`
   initializes a `b3Vec3` with two components where three are needed. Both are pre-existing 2D leftovers
   in the `B3_TREE_HEURISTIC != 0` arm (`:1636`-`:1812`), which is COMPILED OUT today: `B3_TREE_HEURISTIC`
   is 0 at `:1477` and an `#error` at `:1479`-`:1486` refuses to select the unconverted path. Dead, fenced,
   documented; not live. `f555ee4` rewrites this file wholesale, so the port either converts the arm or
   carries it forward fenced as today.
2. Term order in the five `Perimeter(Union(a,b)) - Perimeter(c)` deltas is upstream's exactly: these are
   differences of rounded products, and a reassociation is not free on this tree (the "deliberately NOT
   fused" list — `b3Cross`, `b3MulMV`, `b3Lerp`, each bisected).
3. The degenerate-plane skip at `:1745` is preserved or replaced by L1's guarantee, never dropped.

ACCEPTED REGRESSION, stated in the port record: `b3Perimeter` is a product of widths, so for a box under
about 4 cm on a side every product quantizes to 0 (rule 1) and the rotate deltas read 0 — the rotate
takes the first candidate rather than the best. Quality, not correctness, but a determinism input: our
tree shape differs from upstream's on identical input and our goldens are our own numbers.

CHECKED BY: new `TreeRebuildQuality` asserting `GetAreaRatio` under a measured bound for a fixed 200-box
scene (a number written down, not a tolerance), plus `TreeMoveRefitRebuild` and `TreeQueryBruteForce`.
No TLA+ — arithmetic, not a state machine. HELD: question 3.

## L6 — tree-against-tree traversal and the sorted pair key

STRUCTURE: `b3GatherMovedSiblings`, `b3SelfPairsTask`, `b3GatherCrossSeeds`, `b3CollideCrossPairs`,
`b3TestPair`, `b3AddCandidatePair`, `b3FlushCandidatePairs`, `b3Array(uint64_t) pairKeys` in
`b3TaskContext`, the merge + `QSORT` in `b3UpdateBroadPhasePairs`; `b3DeclareArrayNative(uint64_t)`;
`b3KeyHash` moved to `src/table.h` plus new `b3ContainsHashedKey`. `src/qsort.h` already exists here, so
no dependency on `954cf87`.

GUARANTEES:
1. The emitted pair set equals what brute-force O(n^2) overlap over the moved proxies would emit.
2. Each pair is emitted exactly once: the self-pair seeds are disjoint sibling pairs and the descent is
   cross-subtree, so a duplicate key is a bug. Upstream asserts and skips; we keep both.
3. The sorted key sequence is a function of the pair set alone — independent of worker count, task split
   and tree shape. `b3ShapePairKey` (`src/table.h:27`) already orders the two shape ids, so the key is
   canonical and sorting unique keys is order-independent for any correct sort.
4. `b3CreateContact` is therefore called in the same sequence at every worker count.

CHECKED BY: TLA+ `PairKeySort.tla` — variables the per-worker key arrays and the merged array; actions
Emit(worker,key), Merge, Sort, Consume; invariants 1-4, the sort modelled as "the merged sequence is the
unique ascending permutation". TLC instance 4 shapes (6 possible pairs), 2 workers, any interleaving.
Then `TreeQueryBruteForce` and `TreeCastBruteForce` (set equality via `CompareInt`/`SameSet`, no
tolerance — the two most valuable new subtests), and the suite's cross-worker-count equality, which is
guarantee 3 measured end to end.

CONVERSION WORK, not mechanics: the new test file's generator is
`RandomFloat = (float)( NextRandom() >> 8 ) / (float)( 1 << 24 )`; it becomes an integer scale of the
24-bit random or the suite loses bit-exactness across platforms, which is the point of the fork.
`TreeQueryClosest`'s `FLT_MAX` seeds become `B3_FIXED_MAX` and are then subtracted from — rule 4, L1.
HELD: nothing.

## L7 — broad phase wiring

STRUCTURE: `b3BroadPhase` (`src/broad_phase.h:27`) loses `movedProxies`, `moveArray`, `moveResults`,
`movePairs`, `movePairCapacity`, `movePairIndex`, `b3BufferMove` and gains `int* movedSiblings`;
`solver.c`'s direct `b3BroadPhase_MarkProxyMoved` plus the bullet exclusion; `joint.c`'s `b3BufferMove`
-> `_MarkProxyMovedSerial`; `b3World::compoundShapeCount` with its increment in `shape.c` and its
decrement on both teardown paths in `body.c`; `b3EmitCompoundPairs`; `b3AllocZeroed` -> `b3AllocZero`
across 7 live call sites in `src/compound.c`.

GUARANTEES:
1. `compoundShapeCount` equals the live compound shape count at every step boundary. It gates a fast
   path, so a wrong count changes which pairs are emitted. `b3DestroyBody` tears shapes down without
   going through the shape destroy path, so the second decrement is a real bug fix, not an optimization:
   without it the count leaks and pins the slow path for the life of the world.
2. Every proxy whose fat AABB no longer contains its shape AABB is marked moved in the same step.
3. The compound child query happens in a frame that cannot overflow in either config.

CHECKED BY: `TestCompoundShapeCount`, extended with a `b3DestroyBody` case for guarantee 1's leak path,
seen red first; the determinism suite for 2; a new ludicrous case placing a compound far from the origin
for 3.

HELD: question 5. Upstream demotes via `b3ToRelativeTransform( bodyTransform, b3Pos_zero )`, commenting
"Query bounds are float world space, so the demoted transform is the matching float frame". Narrow, fine.
In `LUDICROUS_MODE` the query AABB is `fixAABBWide` while the compound's baked child boxes are narrow, so
demoting relative to the origin throws away exactly the range ludicrous mode exists to provide.

## The golden plan

All four determinism scenarios are expected to move, and so are the spherical-geometry hashes. The
primary mover is the pair sort: contact creation order changes, graph coloring changes, the solver sees a
different order. Secondary movers, each independently sufficient: the cross-subtree enumeration; the
direct moved-mark replacing the serial `enlargedSimBitSet` union, which changes *when* a proxy enters the
search; the wholesale index change under the sibling-pair layout; and L5's quantize-to-zero rotate deltas.
Upstream moved three of its five golden groups here — that is the signal, not the numbers.

Harvest discipline: one reason per harvest. The branch lands in steps; a step that moves a golden
harvests before the next step starts, with the reason named in the commit. A value is written down only
after it is seen identical at every worker count the suite runs — ragdoll 1 to 5, wave pile 1 to 4, query
spawn 1 to 4, mesh drop 1 and 4 — in narrow and `LUDICROUS_MODE`, and in Debug+VALIDATE+ASan. A sleep
step of 0 means the scene never settled and is read as that, never captured. The values being replaced
are `test/test_determinism.c:37-61`.

## The tracer bullet

Warranted, once, declared. END STATED BEFORE START: upstream's `dynamic_tree.c`, `dynamic_tree.h` and the
scalar `b3AABBV` arm are pasted into a scratch branch with only compile errors fixed and `INFINITY`
replaced by `B3_BOUNDS3_EMPTY`; it runs `TreeQueryBruteForce` and `TreeDestroyScrambled` on a 10-proxy
tree, narrow, Debug+VALIDATE, end to end once. It ends when either passes once or the first assert fires
— whichever comes first, it ends there and is not debugged. WHAT IT PROVES: which arithmetic sites
actually reach a sentinel operand at runtime, and the measured `sizeof`/`_Alignof` of `b3TreeNode` in both
configs. WHAT IS KEPT: that site list, which becomes L1's audit and its assert; the two measured sizes,
which become L2's `_Static_assert`s; and every failure, which becomes an invariant in L3's or L4's
module. Its code is discarded.
