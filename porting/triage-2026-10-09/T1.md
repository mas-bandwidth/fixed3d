# `f555ee4` "Optimize Broad-Phase (#159)" — 2026-09-16, 51 files, +3802/-1830

## 1. What it does

It replaces the move-buffer broad phase with a **tree-against-tree pair traversal ported
from Box2D**. The dynamic tree is re-laid-out: `b3TreeNode` loses `categoryBits`,
`userData`, `parent` and the 16-bit `height`/`flags` pair and becomes a 32-byte record of
`b3AABB aabb` + a bit-packed `uint32_t flagIndex` (bit 31 leaf, bit 30 moved, bits 0-29
sibling-pair index or proxy id) + a 4-byte `height`/`shapeIndex` union; the cold half moves
to a new parallel `b3TreeProxy` array, parents move to a separate `int32_t* parents`, siblings
are paired at even indices, the root is index 0 and index 1 is always an empty sentinel node.
The per-step "moved proxy" bitset + `b3Array(int) moveArray` + `b3MovePair` linked lists are
deleted; workers instead set a `B3_MOVED_NODE` bit with an atomic fetch-or that propagates to
the root, the step gathers moved sibling pairs and does a breadth-first cross-subtree descent
(Ericson 6.3.2) seeded into a parallel search, and each worker appends 64-bit pair keys to a
new `b3Array(uint64_t) pairKeys` in its task context which are then merged and **sorted** so
contact creation order is independent of tree structure.

## 4. Tests added or changed in `test/`

New suite `DynamicTreeTest` in `test/test_dynamic_tree.c` (registered in `test/main.c` and `test/CMakeLists.txt`), run in this order:

1. `TreeLeafRoot` — single-proxy tree, root-is-leaf edge case. Boxes are `{ { -1.0f, -1.0f, -1.0f }, { 1.0f, 1.0f, 1.0f } }` and `b3AABB_Inflate( box, 1.0f )`. **Portable**, literal conversion only.
2. `TreeQueryBruteForce` — random boxes, tree query vs O(n^2), compared as integer id sets through `CompareInt`/`SameSet`. **Portable and the most valuable one**: it asserts set equality, not numeric closeness, so no tolerance is involved.
3. `TreeCategoryFilter` — `maskBits`/`requireAllBits`. Pure bit logic. **Portable.**
4. `TreeMoveRefitRebuild` — moves proxies with `RandomBox( 6.0f, 1.0f )` and validates refit/rebuild. **Portable**, but the generator is the work: `static float RandomFloat( float lo, float hi )` is `(float)( NextRandom() >> 8 ) / (float)( 1 << 24 )` — a float divide. In fixed point this must become an integer scale of the 24-bit random (`B3_FIX`-scaled numerator, integer shift) or the test loses bit-exactness across platforms, which is the whole point of this fork.
5. `TreeDestroyScrambled` — destroy in scrambled order, free-list and `nodeEnd` invariants. Integer only. **Portable.**
6. `TreeCastBruteForce` — ray and box cast vs brute force. Callbacks `static float RayCastCollectCallback(...)` / `BoxCastCollectCallback(...)` return `-1.0f` to continue; locals `float minFraction = 0.0f; float maxFraction = 1.0f;`. **Portable** once the callback signature becomes `b3Fixed` — note the fixed3d callback typedefs already return `b3Fixed`, so the `-1.0f` sentinel becomes `-B3_FIX(1.0)` and the `0.0f < value` guards are plain int comparisons.
7. `TreeQueryClosest` — `static float DistanceToBoxSqr( b3Vec3 point, b3AABB box )`, `float bruteBest = FLT_MAX; float minDistanceSqr = FLT_MAX;`. **Portable with care**: `FLT_MAX` must become `B3_FIXED_MAX`, and CLAUDE.md trap 4 applies — any `B3_FIXED_MAX - x` or `B3_FIXED_MAX * x` on that seed wraps. The file `#include <float.h>` goes away. This is the one subtest where a fixed-point rewrite can go silently wrong.
8. `TreeSaveLoadRoundtrip` — `b3DynamicTree_Load( treePath, 1.0f )` round trip plus a negative case loading a compound path and expecting no tree. **Portable**; the `1.0f` becomes `B3_FIX(1.0)` since fixed3d's `_Load` already takes `b3Fixed`.

Changed elsewhere: `test_world.c` renames `CountEnlargedNodes` -> `CountMovedNodes`, rewrites `TestEnlargedProxyDestroyed` (expectation inverted, plus `b3DynamicTree_Validate` and `ENSURE( tree->dfsOrdered )`), and adds `TestCompoundShapeCount` (pure counting; **portable**). `test_compound.c` swaps `tree.nodeCount > 0` for `tree.nodeEnd >= 2` + `tree.proxyCount > 0` + `tree.proxies != NULL`. `test_container.c` drops its duplicate `b3DeclareArrayNative( uint64_t )`.

## 7. Effort estimate

**22 hunk groups PORT, 14 SKIP (13 CSV + the two float-SIMD arms of `simd.h`, which are one group), 4 HELD (the two version numbers, the `b3MakeEmptyNode` infinity sentinel, the ludicrous-mode compound demotion), plus 3 samples/benchmark groups that can be held as sample content like fixed3d#20/#47.**

**The hard part is `b3MakeEmptyNode`.** Upstream makes the empty node a *permanent, first-class* participant — index 1 of every tree is always empty, every sibling-pair traversal reads it, and `b3UnionPairV`/`b3Perimeter` consume it during refit and rebuild:

```c
B3_FORCE_INLINE b3TreeNode b3MakeEmptyNode( void )
{
	return B3_LITERAL( b3TreeNode ){
		.aabb = { .lowerBound = { INFINITY, INFINITY, INFINITY },
		          .upperBound = { -INFINITY, -INFINITY, -INFINITY } },
		.flagIndex = B3_EMPTY_NODE, .height = 0 };
}
```

Q48.16 has no infinity. - **`meshScale.x * meshScale.y * meshScale.z < 0.0f`**, `src/mesh_contact.c` new `meshFlipped`.   {

The `#ifndef` tunable wrapper is there (ported in 47d7f7c) with value **256**. Upstream's own
comment on that constant — "Increasing this will increase stack usage, so be careful" — is why
the bump is **coupled** to the `mesh_contact.c` arena hunk: fixed3d still has
`int triangleIndices[B3_MAX_MESH_CONTACT_TRIANGLES];` (`src/mesh_contact.c:104`) and

change first, then the constant.**

No other public header changes. (`b3Body_SetSafetyFactor`/`b3BodyDef::safetyFactor` are

**(b) One new test function: `SingleMeshMixTest( int workerCount, DeterminismResult* reference )`**
(112 lines), plus one line adding it to the `scenes[]` array of `SIMDWidthTest`. Its own comment
states its purpose: *"Mesh contacts are grouped across lanes by manifold count and padded to the
largest count in the group. Width 8 groups differ from width 4 groups... The hash covers
velocities and impulses bitwise to catch a padded manifold flipping a signed zero."* It builds a
40x40 wave mesh, drops 64 bodies of four mixed shape types (large box / small box / sphere /
capsule) chosen by an LCG, gives 5/16 of them `rollingResistance = 0.2f`, sets deliberate
**negative-zero** velocity components (`-0.0f`), steps 180 frames, and hashes transforms +
linear/angular velocity + per-manifold `rollingImpulse`/`frictionImpulse`/`twistImpulse` +
per-point `normalImpulse`/`totalNormalImpulse`.

**Portable to fixed point? The scene yes, the test no, and the signed-zero premise is void.**
- **Harness missing.** `grep -rn "SIMDWidthTest\|RunSceneAtWidth\|HashFloats\|EnsureRepeatable\|DeterminismResult" test/ shared/` -> **no output**. fixed3d's determinism tests have the signature `static int SingleMeshDropTest( int workerCount )` (`test/test_determinism.c:254`) — no `DeterminismResult*`, no width-sweep driver, no `HashFloats`. It also has no `SingleRollingMixTest`. All of that arrives from earlier unported commits in the range. The new test cannot compile until the harness lands.
- **Its stated purpose does not exist in fixed3d.** There is no runtime width to sweep (`grep -rn "simdWidth\|B3_SIMD_HAS_WIDTH_8" src/ include/` -> no output); `B3_SIMD_WIDTH` is a compile-time `4` (`src/core.h:79`). A W4-vs-W8 comparison test is a no-op here until `e77352c` (#174) is ported, and `e77352c` is itself unported.
- **`-0.0f` is not a thing.** `b3Fixed` is `int64_t` with `+ - < ==` as plain integer ops; there is no signed zero to flip. The test's headline failure mode is unreachable in fixed point. The *scene* is still valuable (mixed shapes on a fine mesh, ragged manifold counts, rolling resistance) and should be kept as a fixed-point scene with a fresh golden — but it tests a different thing here.
- All literals need `B3_FIX()`: `b3Sphere sphere = {{0,0,0}, 0.3f}`, `b3Capsule`, `b3MakeBoxHull(0.2f,...)`, `b3CreateWaveMesh(40,40,0.5f,0.3f,0.2f,0.3f)` (fixed3d's call sites pass `B3_FIX(...)`, e.g. `test/test_mesh.c:617`), `2.2f * (float)column - 7.7f`, `1.0f/60.0f`.

## 5. Determinism exposure

**Can move a fixed3d golden if ported:**
1. **`b3SATCache` zeroing on culled triangles** (`mesh_contact.c`). Highest confidence mover. Warm-start SAT hints are frame-carried state; clearing them changes next frame's axis search.
2. **Survivor-loop capacity early-out** (`mesh_contact.c`). The `totalPointCount + 3 < pointBufferCapacity` guard now advances per *survivor* instead of per *triangle*, so when culling fires, more triangles fit under the point-buffer ceiling -> different manifold set. Interacts directly with 512.
3. **`b3WarmStartContacts_Mesh` reassociation** (`contact_solver.c`). Bit-level certain to change the hash; algebraically exact, numerically better.
4. **`b3IsShapeFast` CCD gate** (`solver.c`). Changes *whether* CCD runs for a shape. Any scene with a fast body near a mesh moves. Aggravated in fixed point by `rotationChord * radius` quantizing to zero (-> skips CCD that float would run).
5. **`b3ComputeShapeMinExtent` swap** (`shape.c`). Changes `fallbackRadius` for hulls wherever `hull->innerRadius != b3ComputeShapeExtent(...).minExtent`. Moot in fixed3d today — no `innerRadius` field — but a mover the moment that field is added.
6. **Mesh lane counting sort** (`solver.c`). In *upstream* this is a mover (it repacks lanes and changes padding). In *fixed3d* it should be free, because fixed3d's own wide path is documented *"Both paths are bit-identical per lane, so this cannot affect determinism"* (`src/contact_solver.h:76`) — a claim Rowan should re-verify rather than inherit, since it is now load-bearing for a different change than the one it was written for.

**Cannot move a golden:**
- `b3QueryMesh` two-child prune — leaf order provably identical, all comparisons exact int64.
- `b3GetMeshTriangle` inline move — same body, same arithmetic. (Its *existing* `b3FixMul` product bug is pre-existing, not introduced.)
- The lane transform rewrite — bit-identical given `fixMulMV`'s per-product rounding.
- `b3Bump` for `triangleIndices`/`contactCache` — allocation only.
- Stall-logging removal — `b3Log` is observation-only; deleting it cannot change state. (Deleting the *sentinel guards* alongside it cannot either, since they only gated the log.)
- `b3ParallelFor(... 16 ...)` -> `... 8 ...` for `b3FinalizeBodiesTask` — block granularity; fixed3d's determinism tests already assert cross-worker-count invariance.
- Benchmark CSVs, samples, `simd_*.h`.

**On the 512 bump specifically: the diff shows a ceiling change, not a behavior change — but it
is not inert.** `B3_MAX_MESH_CONTACT_TRIANGLES` appears in the diff only as
`triangleCapacity = B3_MAX_MESH_CONTACT_TRIANGLES` and the two array sizings; no clamping,
selection or sort logic changes. So for any contact already under 256 triangles, nothing moves.
**For a contact that was previously truncated at 256, it moves everything** — more triangles
kept -> more manifolds -> different contact set. Whether that is reachable depends on content;
fixed3d's `MESH_DROP` scene is the candidate, and the new `mesh_drop` benchmark (group 18) plus
`SingleMeshMixTest`'s 40x40 wave mesh are precisely the scenes designed to hit it. **Expect
`MESH_DROP_HASH` to move; be suspicious if it does not.** Upstream's own
`MESH_DROP_SLEEP_STEP` moved 217->218.

are two independent solutions to the same problem, and fixed3d's is three months older and has a
measurement attached.** The arithmetic in this commit is unusually benign for fixed point: one
