## 1. `adec25b` "SAT optimizations (#170)" — 2026-09-24

### What it does

Adds an inscribed-sphere upper bound on the separation achievable by any candidate axis
(`dot(axis, centerB - centerA) - innerRadiusA - innerRadiusB`) and uses it to skip face planes and
to pre-filter edge pairs, so complex hulls stop paying for every face and every edge pair. It
precomputes `dot(normal, deltaCenter)` for all faces wide (`b3GetFaceDots`), seeds each face loop
with the most-aligned face to get a separation floor, gathers only the edges whose Gauss-map arc can
still reach the bound (`b3ArcCanReach`), and adds a full-SAT fallback in `b3CollideHulls` when face
clipping produces no points. It also vectorizes `b3FindHullSupportVertex` in `hull.c`.

## 4. `e77352c` "Add support for AVX2 and runtime feature detection (#174)" — 2026-10-04

### What it does

Splits the wide code into width-parameterized `.inl` files compiled twice (`wide4.c` at
`B3_SIMD_WIDTH 4`, `wide8.c` at 8 under `-mavx2`), replaces the single `b3FloatW` lane library with
four backends (`simd_scalar.h`, `simd_sse2.h`, `simd_avx2.h`, `simd_neon.h`) plus a macro renaming
layer (`simd_wide.h`), adds CPUID/XGETBV runtime detection and a per-world `simdWidth` that
dispatches both the contact solver and the hull SAT, raises `B3_ALIGNMENT` to 32, pads hull SoA
arrays to 8, and adds two cross-width determinism tests asserting width 4 and width 8 are bitwise
identical. Authored by Ethan Rutherford, not Erin.

### Tests

Two new test functions, both in the (a) half, and **both are the most portable thing in all four commits**:

1. **`test/test_determinism.c: SingleRollingMixTest( int workerCount, DeterminismResult* reference )`** (+~95).
   An 8x8 grid of mixed sphere/capsule/box bodies with rolling resistance set on ~5/16 of them by
   LCG, stepped 120 times, hashing body transforms **and** the stored manifold impulses
   (`rollingImpulse`, `frictionImpulse`, `twistImpulse`, per-point `normalImpulse`,
   `totalNormalImpulse`). Its own comment states the purpose: *"Rolling resistance is mixed per
   contact and the manifolds have one, two, and four points, so a width 8 constraint can mix lanes
   that width 4 keeps in separate constraints."* **Portable to fixed point, and valuable
   independently of AVX2.** It is a lane-mixing probe for the wide contact solver, and fixed3d has a
   wide contact solver with exactly that concern — plus the `B3_IMPULSE_CAP_GATE` friction/rolling
   cap machinery of CLAUDE.md rule 4, whose six squared-cap sites are precisely "scalar and wide
   share the cold helpers lane-wise, so they cannot diverge". This test is the scenario that would
   *demonstrate* that claim rather than assert it. Fixed-point conversion notes: `HashFloats` must
   become a `b3Fixed` hash (the test hashes raw float bytes "including the sign of zero" — in Q48.16
   there is no signed zero, so that clause simply drops, which is a *simplification*); the float
   literals (`0.4f`, `1.45f`, `0.2f`, `3.0f`, `1.0f/60.0f`) are all `B3_FIX()`-able; the LCG is
   integer and exact. **The golden would be new and would need pinning in both narrow and ludicrous
   modes** (fixed3d's convention, `test/test_determinism.c:48-60`).
2. **`test/test_recording.c: CrossWidthReplay( void )`** (+~100) with helper
   `ValidateReplayAtWidth( const b3Recording* rec, int width )`. Asserts a recording made at the
   native width replays bit-exactly at width 4 and vice versa. **Portable in shape, not in content**
   — it needs `b3SetSIMDWidth`, so it only lands if (a) lands. The fixed3d analogue is
   "a recording made with AVX-512 enabled replays on the scalar path", which is a *stronger* and
   currently untested claim about this tree than anything in its suite: the AVX-512 path's
   bit-identity is asserted by construction and verified per-build in CI, not cross-replayed within
   one binary.
3. **`SIMDWidthTest( void )`** with `RunSceneAtWidth( SceneFcn*, int width, DeterminismResult* )`

   (`SingleMultithreadingTest`, `SingleWavePileTest`, `SingleQuerySpawnTest`, `SingleMeshDropTest`,

   hit count and query hash. Self-skips when native width is 4 (`printf( "  subtest skipped:

- **RESOLVED while writing this report, so the quantization claims above rest on the library, not on recall.** My first greps for `b3FixMul` in `extern/fixed/include/fixed/*.h` returned nothing because the vendored library spells the primitives without the `b3` prefix; `include/box3d/fixed_compat.h` is the drop-in shim (`:82,90,93`: `B3_FIXED_INLINE fixed_t b3FixDiv( fixed_t a, fixed_t b ) { return fixDiv( a, b ); }`, `b3FixMul` -> `fixMul`, `b3FixSqrt` -> `fixSqrt`; `:69`: `#define B3_FIXED_EPSILON FIX_EPSILON`). The actual multiply, `extern/fixed/include/fixed/fixed.h:200-208`:

```c
FIX_ALWAYS_INLINE fixed_t fixMul( fixed_t a, fixed_t b )
{
	// Round half up, then shift out the fraction bits (arithmetic shift)
	fixInt128 r = (fixInt128)( (fixUInt128)( (fixInt128)a * b ) + (fixUInt128)(fixInt128)FIX_HALF ) >> FIX_FRACTION_BITS;
```

  with `FIX_FRACTION_BITS 16`, `FIX_ONE ( (fixed_t)1 << FIX_FRACTION_BITS )` and `FIX_EPSILON ( (fixed_t)1 )` (`fixed.h:37,40,47`). So the quantize-to-zero threshold I invoke throughout is exact and arithmetic, not folklore: the product is formed at 128 bits, `FIX_HALF` = 32768 is added, and the result is shifted right 16. **Any `a*b` whose true product is below `2^-17` in magnitude rounds to 0**, i.e. `|a|*|b| < 7.6e-6`, which is why two values near 0.0027 multiply to zero and why every squared tolerance below ~0.004 collapses (CLAUDE.md rule 7, independently measured there). The saturating branch is `#if defined( FIX_SATURATE )` only, confirming CLAUDE.md's "overflow checks are opt-in ... default wraps" and therefore rule 4's sentinel-wrap hazard.

  adjacent hunks; the per-file totals are exact (`git show --numstat`).
