# Commit 1 — `9e5a4cd` "Optimizations (#161)", 2026-09-20

## 1. What it does

Three independent optimizations plus one physics fix. (a) The contact's cached body-sim index
pair becomes a single ENCODED integer per body (`encodedBodySimA/B`: awake local index, or
`-(staticLocalIndex+2)` for static, or `B3_NULL_INDEX` for asleep), kept persistently correct
across destroy/sleep/wake/transfer instead of being recomputed every narrow-phase step — this
removes the `b3Body` read from the collide hot loop. (b) `b3Shape::fatAABB` moves out of the
shape struct into a new parallel `world->fatAABBs` array indexed by shape id, so the
broad-phase overlap test touches one cache line per shape instead of a whole `b3Shape`.
(c) Restitution is folded into the solve stage (reverted by `79fc559`). (d) A real physics
fix: after a CCD impact, the gravity lost to the time loss `(1 - fraction) * dt` is added back
to the body's linear velocity, respecting the three linear lock flags.

## 3. Public API changes (`include/box3d/*.h`)

Three **breaking** signature changes, one macro removal, two struct changes:

- `typedef void* b3AllocFcn( int32_t size, int32_t alignment )` → `( size_t size, int32_t alignment )`.
- `typedef void b3FreeFcn( void* mem )` → `( void* mem, size_t size )`. **Every user free
  callback gains a parameter.** `b3Free` now passes the *aligned* size, not the requested size.
- `B3_API int b3GetByteCount( void )` → `B3_API int64_t b3GetByteCount( void )`.
- `#define B3_RESTITUTION_ITERATIONS 1` removed from `constants.h`, and its `config.h`
  opt-in comment removed. fixed3d uses it in 4 places in `src/solver.c` plus both headers
  (`git grep -c B3_RESTITUTION_ITERATIONS HEAD -- src include` →
  `include/box3d/config.h:1 include/box3d/constants.h:2 src/solver.c:4`).
  `79fc559` replaces it with a runtime `b3WorldDef::restitutionIterations`.
- `b3Counters`: `int byteCount` → `int64_t byteCount`, moved to the first field; `//! @cond`
  doc suppression removed from `b3Profile` and `b3Counters`.
- `b3Profile`: field `applyRestitution` removed.
- `b3ManifoldPoint`: no field added or removed, but `normalVelocity`'s CONTRACT changes — it
  is now zero unless hit events are enabled on the contact. Any fixed3d test or sample
  reading `normalVelocity` without `enableHitEvents` reads 0 after this commit.
- `include/box3d/base.h` gains `#include <stddef.h>` (for `size_t`).

# Commit 2 — `79fc559` "Optimizations (#168)", 2026-09-24

## 1. What it does

Restores restitution as a post-solve stage with a **new** algorithm: Poisson *kinetic*
restitution, where each point tracks a `restitutionImpulse` accumulator and the restitution
impulse is capped by `restitution * (compressionImpulse + approachImpulse) -
restitutionImpulse`, which upstream's comment claims "guarantees no energy gain". The stage
runs a world-configurable number of iterations (`b3WorldDef::restitutionIterations`, default
2, clamped to `B3_MAX_RESTITUTION_ITERATIONS` 63) and is skipped entirely unless some contact
reported restitution via a new `b3AtomicInt anyRestitution` in the step context. Alongside:
`b3BodyState` is repadded from 56 to 64 bytes and `b3BodySim`'s hot fields are moved to the
front; the wide prepare path converts quaternions to matrices once instead of rotating per
point; and five real bug fixes land (`b3_hadTimeOfImpact` now lives on the body sim so debug
draw sees it, non-dynamic joint enable/disable, a static-tree rebuild that was clearing move
marks, two joint prepare asserts that assumed body B was the awake one, and a `BOX2D_PROFILE`
typo).

**WILL move a golden:** H-A (restitution is now a separate stage with 2 iterations by default,

H-E (removing the tail-lane `memset` changes what the wide solver reads in remainder lanes, and
therefore the per-lane arithmetic, even when the results are later masked — this is the most
likely cause of the `QUERY_SPAWN_HASH` move, since that scene is query-driven and
`WAVE_PILE`'s size makes tail lanes common); H-H (skipping the move-mark clear on a full
rebuild changes which proxies the NEXT broad-phase pass visits, which changes **pair order** —
directly in the brief's list); H-C (a struct relayout changes nothing mathematically in float,
but in fixed point a layout change interacts with the ludicrous-mode wide paths, so treat it
as golden-moving until measured); H-D (if fixed3d's existing formulation differs from
upstream's term order at all, this moves everything — hence "verify term by term").

**CANNOT move a golden:** H-B (new API, defaults chosen so the behavior is the new default
anyway — but note `restitutionIterations = 2` IS a behavior choice, so the *default value* is
golden-moving even though the API is not), H-F, H-G (assert relaxations), H-I, H-J, H-K
(public layout, not internal math), H-L, H-M, H-O, H-P.

The `anyRestitution` atomic gate in H-A deserves one explicit note: it makes the restitution
stage **conditional on scene content**, so a scene with no restitution now skips a stage that
previously ran as a no-op. That is a performance change, not an ordering change, as long as
the skipped stage really was a no-op — which `9e5a4cd`'s `if ( restitution == 0.0f ) continue;`
guarantees for the float path and which must be re-verified for the fixed path, because
`restitution == 0` is an exact compare that fixed point preserves.

velocity`, `(1-fraction) * dt`, and `restitution * (impulseA + impulseB)` in these two commits
is a hazard rather than a translation.
